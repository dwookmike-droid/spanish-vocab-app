# 텍스트 가져오기 (Grok Bot 빌드 메모)

1. Claude Code가 `es/chNN/text/chNN_text.yaml`을 쓰고 `tools/validate_text.py` 오류 0을 확인해요.
2. Grok Bot이 이 폴더를 박스 작업본(`/workspace/trilingual/es/v6`)으로 가져와 `design/build/text_import.py`의 `load_chapter(ROOT, NN)`으로 읽어요.
   - 불러올 때 검증기를 다시 돌리고, 오류가 있으면 빌드를 멈춰요.
   - 결과 구조는 v6 데이터와 같아요: `items`(V3 형식, 강세 `<b>`), `notes`(카드 메모), `order`(sent/clitic/subj/practice/variants + patterns), `opener`, `props`, `scenes`, `extras`.
   - ch01 골드 샘플로 왕복 확인을 했어요: v6 원본 data.json과 items·sent·clitic·subj·practice·variants·scenes 모두 일치.
3. 레이아웃은 `build_v6.py` 계열 템플릿(스킨별)으로 짜고, `build_all.py`가 print PDF(300~320ppi) · screen PDF(150ppi) · web(WebP·MP3 32kbps)을 함께 만들어요(`v6/README_build.md`).
4. 지면에 넘치는 문구가 있으면 해당 필드 경로(예: `words[3].example.ko`)와 남은 글자 수를 적어 Claude Code에 수정 요청을 넘겨요. 글자 수 기준을 바꾸면 `schema/limits.yaml`을 고치고 이유를 여기에 적어요.
5. 사진은 단어 `key`로 연결해요(`{key}.jpg` / 컷아웃 `c_{key}.png`). key를 바꾸면 사진 파일 이름도 같이 바꿔야 해요.

참고: `v6/` 안 스크립트의 경로는 박스 기준(`/workspace/trilingual/es/v6`)이에요. 이 폴더는 원본 보관·공유용이고, 빌드는 박스에서 돌려요.
